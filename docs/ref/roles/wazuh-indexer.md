# wazuh-indexer Role

## Description

The `wazuh-indexer` role installs and configures the Wazuh Indexer on the target node.

The role supports both RHEL-based and Debian-based Linux distributions and handles the full installation lifecycle: providing the node's credentials, generating the certificates of the deployment, staging the node's certificates before the package is installed, installing the package, configuring the node, initializing the indexer security configuration, and verifying that the service is healthy and reachable via its API.

The role can operate in single-node or multi-node cluster configurations, controlled by the `single_node` variable.

## Tasks

| Task | Description |
|------|-------------|
| Import variables | Loads shared variables from `vars/main.yml` and `vars/artifact_urls.yaml`. |
| Provide credentials | Runs the [`wazuh-credentials`](wazuh-credentials.md) role for the indexer keys. |
| Generate certificates | Once, on the control node, only if the deployment has no root CA yet: builds `config.yml` from `instances` and runs `wazuh-certs-tool.sh -A` as root. The root CA and its key stay in `wazuh_certs_ca_dir` on the control node; the certificates are written to `deployment-config-files/wazuh-certificates/` and handed back to the user running the playbook. |
| Stage certificates | Before the package is installed: the root CA certificate (never its key) in `/etc/wazuh/ca`, and the node and admin pairs in `/etc/wazuh-indexer/certs`, with explicit directory modes (`0750`, `0500`). The package then uses them and creates no certificate. |
| Install dependencies | Installs required system packages via the `dependencies.yml` task file. |
| Install package (RHEL) | Downloads and installs the `.rpm` package using `dnf`. |
| Install package (Debian) | Downloads and installs the `.deb` package using `apt`. |
| Configure node | Applies node-specific settings via `config_files_setup.yml`, including `plugins.security.nodes_dn` with the DN of every indexer node, read from its certificate. |
| Reload systemd | Reloads the systemd daemon after installation. |
| Start service | Enables and starts the `wazuh-indexer` service. |
| Initialize security | Runs `indexer-security-init.sh` once, from one indexer node, to load the security configuration into the cluster. |
| Verify API | Waits for the Wazuh Indexer REST API on port `9200`, authenticating as `admin` with the password of the deployment. |
| Configure JVM heap | Sets the JVM heap size to one quarter of the host's total RAM in AIO deployments (`single_node: true`), and to half of it on a dedicated indexer node, unless `wazuh_indexer_heap_size` is set. |

## Certificates

The certificates of the whole deployment are generated by this role, once, on the control node. Running the playbook again reuses the root CA and every certificate. To issue new certificates with the same root CA, remove `deployment-config-files/wazuh-certificates/` and keep `wazuh_certs_ca_dir`.

`wazuh-certs-tool.sh` must run as root, so the user running the playbook needs `sudo` on the control node. The directory in `wazuh_certs_ca_dir` must be owned by root all the way up: the tool refuses a path with a directory that another user owns or can write, such as the playbook directory.

## Usage

This role is used in the `wazuh-aio.yml` and `wazuh-distributed.yml` playbooks. In a distributed deployment, it is applied to each indexer node in the inventory.
